# Усиление обнаружения рисков и модели: проектное решение

## Цель

Повысить полноту обнаружения персональных данных и секретов в русских, белорусских и английских промптах перед конкурсной отправкой. Текст остаётся в браузере. Система может чаще показывать предупреждение «требуется проверка», но уровень «критический» должен оставаться обоснованным. Также адаптировать локальную модель распознавания имён, организаций и мест к учебным промптам.

## Подходы

1. **Расширить правила и нормализацию** — чинить подтверждённые пропуски, учитывать варианты пунктуации, словоформ и обфускации, добавлять негативные примеры от ложных срабатываний. Малый размер, офлайн, объяснимые находки. Это основной путь для секретов и структурированных данных.
2. **Дообучить существующую Slovnet NER** — адаптировать PER/LOC/ORG к коротким учебным запросам на синтетических размеченных примерах и сохранить компактную CNN-CRF архитектуру. Требует проверки переноса, размера файла и качества на разделённых по именам и шаблонам примерах.
3. **Заменить модель на крупную или вызывать внешний ИИ** — может дать контекстный выигрыш, но увеличит загрузку/сложность или нарушит обещание локальной обработки; не включать.

## Решение

Усилить существующий анализатор и тестовую матрицу. Первая подтверждённая проблема — пароль после многословного указания назначения (например, «пароль к школьному кабинету: …»): текущее правило допускает только одно слово контекста. Расширять распознавание по одному классу случаев за раз, добавляя тест до изменения кода.

Параллельно дообучить Slovnet CNN-CRF с исходными PER/LOC/ORG весами, если доступные официальные компоненты и среда позволяют воспроизводимый warm start. Корпус обучения — синтетические, явно размеченные запросы по учебным сценариям; безопасные отрицательные примеры и базовые примеры для предотвращения забывания. Разделять обучение и оценку по шаблонам и вариантам имён. Если точный warm start не поддерживается доступным форматом, не выдавать обучение с нуля на авторских тестах за дообучение: сохранить исходную модель и сообщить техническую причину.

Матрица должна покрыть структурированные контакты и реквизиты, секреты, имена/места, школьный контекст, здоровье/семью, косвенную идентификацию, русские/белорусские/английские формы, намеренно безопасные похожие тексты, обфускацию и предельную длину. Для каждого усиления проверять ожидаемые находки, категорию и уровень, а также ложные тревоги на парных безопасных примерах. Использовать новые вручную составленные случаи и не выдавать их за независимую оценку.

## Цели и ограничения

- Цель: меньше пропусков в поддерживаемых типах данных; сохранять текст локальным и объяснять найденные фрагменты.
- Цель: проверить, улучшает ли адаптированная NER полноту имён/организаций/мест на отложенных синтетических примерах без потери общих сущностей.
- Цель: показывать неопределённость на уровне «требуется проверка», не повышая риск без достаточных оснований.
- Вне объёма: внешние API, увеличение классов NER до телефонов/паролей/документов, юридическая сертификация и заявление о гарантированной защите.
- Ограничение: новых реальных пользовательских текстов для обучения нет. Синтетический корпус и текущие авторские тесты пригодны для технического эксперимента, но не дают независимой оценки качества; это указывать в итоговой оценке.
- Ограничение: браузерная модель остаётся локальной и в отдельном Web Worker; при её смене файл должен получить новую версию для immutable-кэша.

## Проверка результата

Сначала тесты, которые воспроизводят пропуск пароля и ожидают обнаружение секрета; затем исправление. Для модели сравнить исходные и дообученные веса на идентичном изолированном наборе, не использованном для настройки, и проверять регрессии публичных сущностей и ложные срабатывания. После каждого изменения — профильные тесты и полный `npm run test:all`, `npm run check`, `npm run format:check`, `npm run release-check`. Отдельно сравнить новые позитивные случаи с парными безопасными примерами и сообщить найденные ложные тревоги.

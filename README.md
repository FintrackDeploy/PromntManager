# Безопасный промпт

Веб-приложение для педагогов и учащихся: проверяет запрос к генеративному ИИ до отправки, находит персональные данные и лишние подробности по критериям методики (автоматически проверяются C1–C5, C7 и C8; C6 «Перед использованием внешних ИИ-сервисов» — организационный вопрос, он разобран в методике), объясняет риск и предлагает шаблонную безопасную редакцию. Есть тренажёр на синтетических кейсах и печать отчёта.

**Приватность:** всё работает в браузере, на сервере ничего не хранится и не обрабатывается: сервер только отдаёт статические файлы. Текст не отправляется по сети, не сохраняется (ни localStorage, ни cookies, ни аналитики). Единственный сетевой запрос приложения: однократное чтение файла модели с того же сайта (`ner-worker.js`), он ничего не отправляет. `npm test` проверяет это в коде (допустим ровно один `fetch('ner/ner-v2.bin')`), а также что политика CSP одинакова в `index.html`, `_headers` и `nginx.conf`. Офлайн-кэш Service Worker содержит только файлы приложения.

## Возможности
Проверка по критериям C1–C8, подсветка и объяснения, безопасная редакция (копирование, .txt, печать), загрузка .txt/.md/.csv/.docx локально (в .docx читаются текст, колонтитулы, сноски и комментарии), тренажёр из трёх упражнений (найди риски, перепиши безопасно, отправлять или нет) с кейсами, собираемыми заново из вымышленных данных, методика занятия, страницы приватности, PWA-офлайн.

## Нейросеть
Для имён, организаций и мест используется **Slovnet NER** из проекта Natasha (MIT): эмбеддинги Navec + формы слов → три свёрточных слоя → CRF. Модель обучена на новостных текстах. Вывод перенесён на JavaScript (`assets/ner.js`) и работает на устройстве без сети в отдельном потоке (Web Worker, `assets/ner-worker.js`), поэтому интерфейс не зависает на длинных текстах. Сначала сразу показывается результат правил, затем он дополняется ответом нейросети. Веса (~9 МБ, бинарный файл `assets/ner/ner-v2.bin`, словарь Navec сокращён до 60 000 слов: файл на 35% меньше (14 → 9 МБ), на 246 тестовых текстах сохраняется 97% находок полной модели) загружаются один раз и кэшируются; результаты считаются по предложениям и кэшируются, поэтому правка текста пересчитывает только изменённые предложения. При смене модели переименуйте файл (`ner-v3.bin` и далее: старый лежит в кэше как `immutable`) и обновите `ner-worker.js` и тесты. Пересборка весов: `pip install natasha`, затем `python tools/export_ner.py [размер_словаря]` (по умолчанию 60000; записывает `assets/ner/ner-v2.bin`).
Правила и нейросеть дополняют друг друга: нейросеть находит имена вне словаря, правила закрывают телефоны, документы, секреты и контекст. Поверх модели стоят фильтры от типичных ошибок (слово-команда в начале запроса, одиночные «имена» без признаков фамилии).

## Быстрый старт
- Локально: откройте `index.html` в браузере (офлайн-режим PWA включается при размещении по http/https).
- Сервер для разработки: `npm start` (нужен Node 18+, без зависимостей, слушает только 127.0.0.1 и отдаёт заголовки из `_headers`).
- Установка: `npm ci`. Тесты и метрики: `npm test`. Сквозная проверка интерфейса в jsdom (реальные `app.js` и `ner-worker.js`, XSS, .docx, «бомба» в .docx): `npm run test:dom`; всё сразу: `npm run test:all`. Форматирование: `npm run format` (Prettier).

## Данные и архитектура
- Все скрипты общаются через один объект `BP`; других глобальных переменных нет (это проверяет `tests/dom.js`).
- **`assets/rules.json`** — данные, которые правят методисты: критерии C1–C8, тексты находок и рекомендации, замены `[...]`, уровни риска, учебные примеры, словари (имена, города, термины здоровья и семьи, тревожные признаки, известные деятели, страны и т. д.). Из него командой `npm run build:rules` собирается `assets/rules.js` (подключается тегом `<script>`, поэтому работает и при открытии файла с диска). `npm test` проверяет структуру, регулярные выражения, дубликаты и синхронность двух файлов. Версия и дата правил (`rules_version`, `rules_date`) должны совпадать с `package.json`.
- **Остаётся в `assets/analyzer.js`:** регулярные выражения с проверками и контекстом (телефоны, документы, адреса, сочетания признаков) и правила сочетаний. Их нельзя описать данными без потери точности; методисту здесь нужен разработчик.

## Структура
`index.html`, `404.html`, `assets/` (стили, шрифты, `vendor/jszip`, иконки и печать логотипа; анализатор `rules.js` (собирается из `rules.json`), `analyzer.js`, нейросеть `ner.js` + `ner-worker.js` + `ner/ner-v2.bin`, интерфейс `app.js`, тренажёр `trainer.js`), `sw.js` и `manifest.webmanifest` (PWA), `tests/` (авторские промпты и имена, регрессии, устойчивость, время, официальные кейсы КОИ, развёртывание, DOM; `tests/all.js` запускает набор проверок со сводкой), `tools/build.js` и `tools/site-files.js` (сборка `dist/` и единый список файлов сайта), `LICENSE`, `.github/` (CI и Dependabot), `tools/` (`serve.js`, `export_ner.py`), `deploy/` (nginx), `Dockerfile`, `docker-compose.yml`, `_headers`, `.github/workflows/pages.yml`.

## Деплой
1. **GitHub Pages:** загрузите проект в репозиторий, в Settings → Pages выберите источник «GitHub Actions». Workflow запускает тесты и публикует сайт.
2. **Netlify / Cloudflare Pages:** публикуйте корень проекта как статику, заголовки безопасности берутся из `_headers`. **GitHub Pages не применяет `_headers`:** там работает только политика CSP из `<meta>` в `index.html` (она закрывает утечки: скрипты и сеть только со своего сайта), но нет `frame-ancestors`, `X-Frame-Options` и `nosniff`. Для школ и организаций надёжнее Cloudflare Pages, Netlify или свой nginx.
3. **Docker:** `docker compose up -d --build`, сайт на `http://localhost:8080`. Для HTTPS поставьте перед контейнером reverse proxy (Caddy, Traefik, nginx с сертификатом).
4. **Свой nginx:** скопируйте файлы в корень сайта и используйте `deploy/nginx.conf`.

Сборка для публикации: `npm run build` (папка `dist/`). Если вы ставите сайт за собственным HTTPS-прокси, добавьте там заголовок `Strict-Transport-Security` (в приложении его выставлять нельзя: он относится к уровню TLS).

При выпуске новой версии меняйте `version` в `package.json` и `V` в `sw.js` (`bp-<версия>`): `tests/deploy.js` проверяет, что они совпадают. Модель, шрифты и библиотека лежат в отдельном кэше и не скачиваются заново при обновлении.

## Ограничения версии 1.7
- При открытии приложения локальная модель загружается автоматически (около 9 МБ) и затем кэшируется браузером. Отдельного переключателя модели и режима экономии трафика в интерфейсе нет. Если модель недоступна, правила продолжают работать; поиск имён вне словаря будет слабее. На слабых устройствах длинный текст может считаться несколько секунд, интерфейс работает отдельно от модели.
- Нейросеть распознаёт только имена, организации и места и хуже работает на разговорных текстах, опечатках и редких именах. Косвенная идентификация без явных маркеров не находится.
- Наборы промптов и имён для `npm test` составлял автор проекта; наборы `holdout.json` и `blind.json` также использовались при доработке анализатора. Их метрики показывают прохождение этих конкретных примеров, но не являются независимой оценкой качества на новых запросах. В текущей сверке переноса NER на Natasha найдено 37 из 39 эталонных сущностей и 8 лишних до фильтрации.
- Нормативная сверка проведена частично (см. `NORMATIVE_CHECK.md`): подтверждены реквизиты Закона № 99-З и Указа № 422, а форматы белорусских документов (личный номер, серия паспорта) авторитетным источником не подтверждены. Заключение юриста не заменяет.
- Без нейросети имена вне словаря находятся хуже: на 43 размеченных именах правила находят 92% русских, 89% белорусских и 100% английских, с нейросетью 96%, 100% и 100% (`npm test`, `tests/names.js`). Оба набора использовались при доработке правил, поэтому цифры оптимистичны.
- Результат не является гарантией безопасности и юридическим заключением.

## Дорожная карта
независимая оценка качества на новом наборе, вынос оставшихся регулярных выражений из `analyzer.js` в данные, расширение набора до 100–200 примеров, независимая оценка, пилот в школе, проверка в разных браузерах и на телефонах. Docker-образ закреплён по digest в `Dockerfile`.

## Что ищет анализатор
Контакты (email, телефоны РБ и РФ в разных записях, в том числе без кода страны, соцсети и ники, мессенджеры), документы (идентификационный номер, паспорт, УНП/ИНН/СНИЛС, карта с проверкой Луна, IBAN с проверкой контрольной суммы, CVV, дата рождения и «г.р.», номер авто), адреса (улицы в любых падежах, «им.», город + улица, подъезд/домофон/индекс, координаты), имена и ФИО (правила, нейросеть, инициалы, имя + отчество, роль + фамилия, латиница; белорусские буквы і, ў), школа (в том числе по названию и номеру), класс, населённый пункт и район, редкие обстоятельства, здоровье, семья и социальное положение, секреты (пароли, токены, ключи, строки подключения, параметры ссылок, PIN, коды из SMS, IP и MAC), запросы на диагноз и решение о человеке, тревожные признаки. Понимает искажения записи (невидимые символы, двойники букв, «собака/точка»), русский, белорусский и частично английский.

## Качество (честно)
`npm test` запускает авторские размеченные наборы и проверяет заданные ожидаемые находки, пропуски, приватность и другие свойства. Все наборы промптов, включая 34 примера `holdout.json`, 33 примера `blind.json` и 37 примеров `extra.json`, участвовали в разработке или последующих проверках по замеченным ошибкам; называть их независимыми оценочными выборками нельзя. Тесты КОИ проверяют 8 официальных кейсов из положения, но такая небольшая подборка тоже не измеряет качество на реальном потоке запросов. Ранее на тогдашней версии анализатора и одном из авторских наборов наблюдались точность 90% и полнота 82%; после правок эта выборка перестала быть независимой, поэтому эти числа не следует считать текущей оценкой качества. Для внешней оценки нужен новый набор, собранный и размеченный другими людьми — например, методистами и педагогами — и не использованный при настройке анализатора.

## Аудит версии 1.6
Перед выпуском 1.6 проведена проверка на ~45 новых запросах, написанных не при подборе правил. До исправлений на 20 безопасных запросах было 10 ложных тревог (в том числе ложный уровень «высокий»), а запросы про ребёнка со словами «по теме» и диагнозом получали «нет рисков». После исправлений на тех же 20 запросах остаётся одна ложная тревога уровня «требуется проверка»: дата с годом в арифметической задаче («12.05.2010 минус 3 дня»); дата с годом может быть датой рождения, поэтому правило оставлено намеренно. Эти запросы теперь вошли в тесты, поэтому для них метрика уже не независима: оценку качества по-прежнему нужно делать на новом наборе, размеченном другими людьми.
